# Ubuntu terminal runtime

The Bare Linux icon starts `UbuntuRuntimeService` in the separate `nom.vrd:ubuntu` process after the existing image installer completes, then opens `http://127.0.0.1:8766/terminal` in the browser once the HTTP listener is ready. Legacy images retain their original launch path. Closing or destroying `LaunchActivity` no longer schedules `System.exit(0)`. The terminal service has foreground type `specialUse`, a visible Stop action, and a partial wake lock owned by the running terminal. Closing the interface, closing the browser tab or unbinding a client does not stop the terminal.

The native `libnomone_pty.so` creates a Unix98 PTY, starts a session with a controlling terminal, and executes the existing packaged NoMone PRoot and loader with Ubuntu Bash. PRoot enables `--link2symlink` and the original NoMone `-L` symlink-size correction so Android-hosted Ubuntu package updates can create the backup links required by dpkg. Input, signals generated by terminal control characters, job control and terminal resize use the real PTY. Shared phone storage is available at `/storage` and `/sdcard`, and the original NoMone host-filesystem view is available at `/host-rootfs`. Bindings also expose `/mnt`, `/data`, mount information and the standard file-descriptor paths. The guest command clears the Android loader search path after PRoot starts so Ubuntu executables use their Linux libraries. These paths retain the access of the Android app UID. The terminal is headless and does not start the desktop or audio stack.

The service exposes an app-internal Android Messenger binder. Start the service from the foreground before binding. `Message.arg1` is copied to replies for request correlation. Every reply has `ok`, `session`, `running`, `pid`, `exit` and `runtimeError`. A failed request also has `error`.

| Message | Value | Bundle input | Reply additions |
| --- | --- | --- | --- |
| START | 1 | None | Current session; does not duplicate an active shell |
| WRITE | 2 | `session`, byte array `bytes` | Acknowledgment |
| RESIZE | 3 | `session`, integer `rows`, integer `columns` | Acknowledgment |
| READ | 4 | `session`, long `cursor` | byte array `bytes`, long `cursor`, boolean `truncated` |
| STATE | 5 | None | Current session state |
| STOP | 6 | None | Stops the shell and service |

READ is non-destructive. Independent clients retain their own cursor and can reconnect to the same session. The ring retains the most recent 65536 bytes and each reply returns at most 16384 bytes. `truncated` reports that a requested cursor predates retained output. Clients should decode bytes incrementally because UTF-8 characters can span replies. WRITE accepts at most 16384 bytes per request.

The service uses `START_NOT_STICKY`: Android process death ends the shell, and the next explicit start creates a new session ID. Reconnecting to a living service preserves the shell; this does not claim shell survival across process death, force-stop or reboot. The Stop notification terminates the browser session, SSH daemon and HTTP listener.

## Browser transport

`TerminalServer` listens on `0.0.0.0:8766`. `/terminal` serves the bundled xterm.js interface, `/health` reports the actual session state, and `/ws` upgrades to a WebSocket. Other devices use `http://PHONE_IP:8766/terminal`. Browser files are embedded assets; there is no runtime CDN requirement. The notification also opens the terminal URL.

Client binary frames contain raw terminal input. Client text frames are `resize:ROWS:COLUMNS` or `ack:CURSOR`. Server binary frames begin with an unsigned 64-bit big-endian output cursor followed by PTY bytes. Server text frames are JSON state, reset or truncated events. Each connection retains its own cursor and sends an acknowledgment after xterm has processed its output frame; the server then sends the next chunk. Reconnect uses `/ws?session=ID&cursor=CURSOR`, while a page reload replays retained output into a fresh terminal renderer. The transport supports WebSocket fragmentation, ping, pong and close frames. Disconnect does not terminate the PTY.

## SSH

The same foreground runtime supervises Dropbear inside Ubuntu on `0.0.0.0:8022`. Login uses the selected Ed25519 client key and user `root`. Each SSH connection opens its own Ubuntu shell or executes its requested command in the same root filesystem used by the browser. The SSH daemon stays active when the browser shell exits. The partial wake lock is released when both managed processes have ended.

`UbuntuSsh` installs the pinned Ubuntu22.04 ARM64 runtime payload, preserves existing authorized keys, adds the selected public key once, and generates a persistent ECDSA server host key on first startup. Password files are preserved. Payload provenance, package URLs and hashes are recorded in `assets/linux/ssh-runtime.json`. The payload contains files from the named Ubuntu packages and does not claim a dpkg package installation.

The local client configuration is in the retained build directory as `ssh-config`. Run `ssh -F PATH_TO_BUILD/ssh-config nomone`. The client ZIP contains the key files and a portable configuration; after extraction, run `ssh -F ssh-config nomone` from that directory. For another device, override `HostName` with the phone IP. The app's `/health` response includes `ssh.port`, `ssh.running` and `ssh.error`.

Run `.github/scripts/test-ssh.py` on ARM64 Android to exercise the real Ubuntu image, original NoMone PRoot, payload installation, existing-key preservation, stable host identity, root key login, exit status, interactive PTY, Ctrl-C and another login. Other CI hosts report the runtime test as not executed; `.github/scripts/verify-ssh.py` still verifies the bundled ARM64 binaries and APK integration there.

Build native code with `python tools/build-pty.py` using Android NDK 27.2.12479018 or the ARM64 Android compiler in Termux. Rebuild Java/Smali with `python tools/build-server-java.py`. Run `.github/scripts/test-pty.py` for actual PTY behavior and `.github/scripts/verify-runtime.py` for source/native/APK integration. On Termux the PTY integration test executes the embedded Ubuntu ARM64 image using the original NoMone PRoot; on Linux CI it executes host Bash. Full Android service lifecycle validation requires installation and execution of the APK.

## Independent browser terminals

Each `POST /sessions` starts a fresh Ubuntu Bash process with a separate Unix98 PTY and UUID. `GET /sessions` lists IDs, process IDs, exit status and running state. `/ws?session=ID&cursor=CURSOR` binds permanently to that ID; another session becoming active never redirects an existing connection. `POST /sessions/ID/close` stops that terminal only. The foreground Stop action stops all browser terminals and SSH.

The browser creates a session on a fresh `/terminal` page and stores its ID in `/terminal?session=ID`. Reload and Herverbinden reconnect to that same ID. Nieuwe terminal creates a new shell, the selector switches between existing shells, and Open in tabblad opens another view of the selected shell. Closing a browser tab leaves its process running. Each shell owns its environment, working directory, process group, size and output history; files in Ubuntu remain shared. The wake lock remains held while any browser shell or SSH daemon runs.

## Android and Ubuntu file workspace

The browser's right pane places Android above Ubuntu, with a direction selector and copy/move/remove actions between them. Both pane paths are editable; directory buttons, parent navigation, name filters, select-all and per-entry checkboxes operate on real filesystem entries. The pane width supports pointer resizing and keyboard arrow keys. At narrow widths the terminal and file workspace stack vertically. Last-used pane paths and width are retained by the browser.

`GET /files/list?side=android|ubuntu&path=ABSOLUTE_PATH` lists actual names, directory/link state, byte sizes and modification times. Listing errors remain attached to the attempted path; the UI never labels previous-directory entries as the new directory. Visible folders refresh every 2.5 seconds. `GET /files/jobs` reports asynchronous operations and their real completion/error state. `POST /files/jobs` accepts an URL-encoded body with `operation=copy|move|remove`, `from`, `to`, `target` and repeated `source` paths. Progress counts completed selected items, including a selected directory as one item; it does not claim byte-level progress.

File workers inherit their own pipes directly; terminal-only standard-stream path bindings apply to PTY launches. File commands run through independent PRoot processes and do not share a terminal input queue. Android paths resolve through the existing `/host-rootfs` view with the app's actual access; Ubuntu paths retain guest symlink semantics. Copy uses GNU cp recursive replacement semantics, move uses GNU mv, and remove recursively deletes the explicitly selected entries. No shell interpolation is used for filenames. Operations update real persistent files; browser tab closure does not stop a running file job while the runtime remains alive. Global Stop closes the file workers and runtime. The job list belongs to the living service and is not an on-disk history across process death.

Run `.github/scripts/test-files.py` for binary hash preservation, recursive copies, overwrite behavior, reverse-direction moves, deletion, special filenames, symbolic links, failed-operation reporting and independent terminal operation. Actual Android storage permission and browser interaction are verified separately on the installed APK.
